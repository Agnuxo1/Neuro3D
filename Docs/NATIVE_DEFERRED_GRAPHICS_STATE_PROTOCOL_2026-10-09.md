# Prospective native deferred3D coherent state and equivalent forward baseline

The original native full-training attempt remains partial and null. Its first complete120-input/16-parameter state passed numerical gates but cost322.45s for transport and CPU merges, suggesting that redundant captured-triangle selection would exceed the fixed full-training envelope.

This original implementation applies deferred shading: separate actual captured-triangle raster/depth selection from later fullscreen optical shading. [Shishkovtsov's primary engine account, NVIDIA GPU Gems2](https://developer.nvidia.com/gpugems/gpugems2/part-ii-shading-lighting-and-shadows/chapter-9-deferred-shading-stalker) describes the geometry-buffer and later shading stages; that established technique is attributed here, without copying implementation or adopting its performance claims.

Our first pass obtains actual GPU object, primitive and approximate distance readbacks. Cache identity includes exact represented ray origin/direction and previous-plane exclusion; any actual geometry update clears it. Only these actual GPU candidates, current captured planes/materials and current incoming complex fields/tangents enter the optical shader. The FP64 expressions for ray-plane distance, coherent phase and optical derivatives are unchanged. No expected CPU hit, phase or transfer/Jacobian matrix enters that shader. Complete-family exact proof, every candidate/primitive/current-distance check, binary64 value/tangent echoes and synchronous GL/context gates remain mandatory.

Before any native execution publish and verify the profile/receipt on main and the scientific branch. The continuing GitHub authorization applies; external/IPFS remains pending. A single paired cost has no confidence interval and includes its declared order/cache context. A new frozen full-learning profile is required afterward.
