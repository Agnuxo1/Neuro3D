# Prospective native geometry-engine ablation: identical exact refinement

The previous GPU v2 route was 2.847 times faster than the original exact CPU builder, but changed both the candidate engine and the verification algorithm. That result does not isolate a GPU advantage.

This [profile](research/native_geometry_ablation_profile_2026-10-09.json), with [prospective GitHub authorization](research/native_geometry_ablation_registration_2026-10-09.json), compares Blender's native CPU `mathutils.bvhtree.BVHTree` against native OpenGL vertex/fragment raster depth selection on the same actual captured geometry. Both use exactly the same rational selected-plane, Gram triangle-support, positive square-interior and exhaustive nearest-competitor verification, source-driven frontier, branches, coherent CPU phase rule and candidate budgets. No expected hits enter either engine. Wrong candidates produce incomplete graphs; no CPU replacement hit is permitted.

Three pairs alternate CPU/GPU, GPU/CPU, CPU/GPU. Construction timing includes each engine's fresh geometry packing/BVH building or shader compilation/vertex upload, frontier queries/readback and exact refinement. Each of six graphs must reproduce all exact historical nodes, roots and order. The GPU graphs additionally undergo the independent full 133-state/186-edge/17,060-path audit and all150 phase-aware native field/power outputs and decisions at unchanged1e-11 tolerances. Both engine metadata and full raw query evidence are retained. The fixed300-second/4,000MiB RAM/2,000MiB owned RSS envelope and shared GPU FIFO remain unchanged.

Six software controls pass, including wrong-candidate rejection, missing-readback rejection, closed-boundary rejection and truthful CPU/GPU metadata. They are software tests, not evidence that a native engine executed. Actual execution is allowed only after all source/profile/authorization bytes are published and remotely verified. No speed advantage, physical precision, RT-core execution, AMD result or system energy claim is assumed. Three pairs on a shared host remain exploratory; this experiment isolates the candidate-engine substitution within the common proof pipeline, not a universal hardware advantage.
