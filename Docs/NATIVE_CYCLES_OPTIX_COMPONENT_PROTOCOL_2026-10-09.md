# Installed Blender Cycles OptiX surface-candidate component

This prospective trial uses the already installed Blender4.5.14 Cycles OptiX backend and RTX3090. No new SDK is installed and no new SDK agreement is accepted. The protocol, source bytes and registration receipt are published in main and the scientific branch before shared-FIFO execution. External/IPFS registration remains pending under the previously authorized GitHub continuation.

The component builds native captured-triangle meshes and an isolated owned render scene. Only the fixed OptiX GPU device is enabled. A one-sample orthographic pixel of1e-7 Blender units emits object ID, global face ID and projected surface position to lossless32-bit EXR. CPU camera transforms, shader inputs, native float32 mesh/camera representation and the finite pixel footprint are explicitly approximate. No expected hit, optical transfer weight or Jacobian is supplied to the renderer. Denoising and adaptive sampling are disabled.

The emitted pixel is a surface candidate. The common exact verifier must independently admit the requested represented ray: positive plane intersection, closed triangle support, positive interior-neighbourhood witness and exhaustive exclusion of closer competitors. The previous object is omitted only after proof of exact transverse zero contact. An incorrect or missing candidate produces an incomplete/null trial; it is never replaced by a CPU hit. Full source-driven branching must recover133 states,186 edges and17,060 represented terminal paths. This uses OptiX rendering as actual geometry computation; rendered brightness is not the optical neural output.

All150 encoded native inputs are propagated through the exact-verified graph using the existing CPU coherent phase rule, with identical decisions and field/power discrepancies≤1e-11. A CPU BVH run uses the same exact verifier and must recover the same graph. One full pair provides measured component costs; it does not establish a statistical or universal GPU advantage. Actual RT kernel counters are not measured by this protocol, so device/backend execution is distinguished from counter-level proof. This component does not demonstrate GPU coherent fields, gradients, training, AMD or physical optical fidelity.

Fixed limits:900seconds, oneCPUcore,4,000MiB free RAM before trial,2,500MiB floor,3,000MiB owned RSS,256MiB raw evidence,8,192MiB sampled whole-device GPU memory and80°C. Original attempts and thresholds are retained on failure.
